# 書寫引擎與筆順素材方案

## 第一版涵蓋範圍（總共 132 字元）
- 韓文 Jamo：19 子音＋21 母音＝**40**（詳 `data/character_inventory.json`）。
- 日文基本平假名：**46**；基本片假名：**46**。
- 濁音、半濁音、拗音、韓文完整音節拼寫：後續可擴充，但第一版 132 個的判定不可缺漏。
- 日文漢字：**只提供振假名及音訊**，不做筆順與手寫判定。

## 外部素材調查
1. 日本假名 SVG：`https://github.com/parsimonhi/animCJK`，`svgsJaKana` 包含假名筆順動畫 SVG。Kana 相關 SVG 可依專案說明選擇 LGPL 路線；使用前仍需閱讀 COPYING。
2. 韓文字母示意圖：`https://github.com/MagisterAdamus/hangeul-stroke-order`，提供 35／40 字母的 SVG 筆順圖，5 個緊音子音未收錄，採 CC BY-SA 4.0。**圖形帶箭頭、編號，不等於可直接判定手寫的中心線。**
3. `animCJK` 的 `svgsKo` 主要是韓國漢字（Hanja），**不是韓文 Jamo**，不能誤當韓文 40 音解決方案。
4. Pointer Events：https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events

## 轉換為統一軌跡格式
每個字元定義 `id`, `language`, `display`, `viewBox`, `strokes[]`，每筆 `path` 為有順序的 SVG 中心線及 `order`、`start`、`end`、方向資訊。
- 不能從普通輪廓 SVG 未經人工確認就假設中心線與正確筆順；先檢查第三方資料是否有可用路徑。
- 初期應做 3 字原型 `ㅏ`, `あ`, `ア`（包含兩種語言和兩種假名）。
- `ㄲ/ㄸ/ㅃ/ㅆ/ㅉ` 等缺少示意圖者，依正式規則人工整理雙字母筆順並確認來源與授權。

## 動畫和字框
- 顯示田字格／中心十字線／四周正方形字框，可切換指導線。
- 「示範」沿路徑依筆順逐筆顯示，標出第幾筆、起點及箭頭。
- 「跟寫」有淡色筆跡／路徑；目前一筆完成後提示下一筆。
- 「獨立寫」保留格線，隱藏字形；可清除、重做、顯示答案。
- 只在書寫區域使用 `touch-action:none`，並處理 `pointerdown/move/up/cancel`, `setPointerCapture`，以減少手指拖動時頁面跟著捲動。

## 筆畫判定（教學用途，不能冒充完美辨識）
1. 將 SVG viewBox 與手指軌跡轉入同一組正規化座標，支援高 DPI、縮放與手機橫直切換。
2. 確認筆畫數、筆畫順序；檢查每筆起終點位置和方向。
3. 對軌跡重採樣，採用對起點偏移、形狀和順序容忍的距離（可先用 DTW／離散 Fréchet 等可解釋方法），設定合理誤差範圍。
4. 即時回饋應指出哪一筆可能錯誤，並允許手動看示範／重畫；避免因手指較粗而過度嚴苛。
5. 不以簡單 bounding box 重疊率宣稱判定正確；要有成功／錯誤實例的測試集。

## 實施順序與停止條件
A. 先驗證日本假名可取得**有方向的逐筆路徑**；韓文 SVG 可合法使用並能補齊 40 字元。
B. 用 3 字做手機真機原型，完成動畫、跟寫和基本判定。
C. 達到原型驗收後，再擴展至 132 字；檢查素材授權和每個字元的筆順。
D. 缺路徑、不確定筆順或授權不明時，標 `not_ready`，**不能以可畫字體輪廓假裝筆順已完成**。

## Phase 0 磁吸描寫實作（2026-10-31）
- 僅三字既有中心線，未修改素材或詞庫。原始筆跡原先直接顯示，故手指偏差可見；原座標換算包含邊框，可能產生小幅偏移，未證實為真機歪斜唯一原因。
- [Hanzi Writer 官方文件](https://hanziwriter.org/docs.html)：有 `onMistake`／`onCorrectStroke`、`leniency`、`acceptBackwardsStrokes=false`；[程式 MIT 授權](https://github.com/chanind/hanzi-writer/blob/master/LICENSE)。直接整合需適配三字資料及既有事件／渲染，成本高於沿用中心線；只借鑑逐筆回饋思路，未複製程式或加入相依。
- [svg-path-properties](https://github.com/rveciana/svg-path-properties) 為 MIT，提供 Node／Canvas 路徑長度與採樣；本案瀏覽器已有原生 `getTotalLength/getPointAtLength`，故不安裝。測試沿用既有 M/L 中心線與純幾何採樣。
- [AnimCJK 授權](https://github.com/parsimonhi/animCJK/blob/master/licenses/COPYING.txt) 的假名選 LGPL-3.0-or-later；[Hangeul Stroke Order](https://github.com/MagisterAdamus/hangeul-stroke-order) 為 CC BY-SA 4.0，只有示意圖。沿用已附原檔、署名與授權，不聲稱使用 Duolingo 私有演算法。
- 統一 1024 正方形 viewBox，`getScreenCTM().inverse()` 映射觸控；保留 `rawPoints` 與已完成原始軌跡；引導顯示 `snappedPoints`，自由寫仍顯示原軌跡。書寫層 clip 到字框，出框、取消或尺寸改變取消當筆，不補畫。
- `GUIDE_DEFAULTS` 集中初值：起點 8%、磁吸 7%、最大偏離 12%、進度至少 85%、原始移動距離貼近比例至少 75%；可透過逐字／逐筆 overrides 調整。完成須抬指，禁止只靠終點距離判斷。
- 4 viewBox 單位取樣；只投影到當筆已達弧長之後的有限窗口；窗口由原始移動距離 ×1.6 加 0.8% 裕量決定，最多前看 12% 框寬（支援較低事件頻率），不全域搜尋。單次輸入跳躍超過 12% 拒絕；反向累積淨移動超過 6% 拒絕，正向移動會抵銷微抖。
- `waiting → drawing → validating → accepted/rejected`；接受後播放 450ms 正確筆畫，再進 `waiting/completed`。取消後的 pointerup 不會完成；錯序、反向只提示重畫，不顯示懲罰分數。原始軌跡以距離加權衡量貼近率，避免用大量停留點灌水。
- 仍需 iPhone Safari 人工驗收：磁吸平順度、手指遮擋、快速轉彎／慢速抖動、多指／取消、旋轉／縮放後對齊與畫布外捲動。三字素材人工筆順審查仍待完成，未擴充 132 字。

## 2026-10-31 字形根因修正（取代以上假名取線與顯示方案）
- 根因：AnimCJK 的揭露動畫折線有輪廓遮罩配合，不能直接裸露為字形中心線。先前誤取它作參考與判定目標，測試又只對同一錯誤資料比對；因此通過不代表自然字形。`あ` 第三筆及 `ア` 都受影響，`ㅏ` 兩筆直線未發現同類素材問題。
- 改用 KanjiVG 固定版本 `70a0b7ae0c18ceb5cb358274b029cce0234a43bc` 的 `03042.svg`／`030a2.svg` 原始 Bézier 曲線，CC BY-SA 3.0。曲線與控制點只以 1024/109 等比例換算，不自行繪製或平滑猜測；保留三／兩筆順序、方向與原檔授權。
- 引導線、進行中的磁吸揭露、示範、接受動畫與深色完成筆畫都直接使用同一條 `character.paths[i]`。先前完成筆畫是部分 `snappedPoints` 重建折線，沒有直接用 raw，但不能保證與完整標準路徑完全一致。現在 raw 僅供判定；自由寫仍原樣顯示 raw。
- 全部維持 1024 正方形 viewBox、等比例縮放與 CTM 反矩陣，未找到非等比例 CSS 拉伸的證據。未取得使用者當時的筆跡事件紀錄，不能把所有舊手機偏移都歸因為座標錯位。
- 判定漏洞：全筆 75% 貼近率會稀釋長筆的局部偏離。原五項門檻完全不變，另加「超出 7% 磁吸範圍的連續原始移動超過框寬 4% 即拒絕」，保留起點、反向、原始沿線比例與至少 85% 進度檢查。
- svg-path-properties 僅作開發／資料驗證與 Node 測試用途（MIT），不進入前端 bundle；用獨立解析器讀完整曲線。來源回歸逐項比較命令、所有控制點、縮放比例及方向，避免只對錯誤資料自我驗證。

## 高寬容度練習（目前行為，取代先前嚴格形狀門檻）
- 使用者改以熟悉筆順為目標；`GUIDE_DEFAULTS` 初值為 15% 起點、13% 磁吸、20% 最大偏離、75% 最低進度、60% 原始沿線比例。標準曲線與完成筆跡不變，自由寫維持原始筆跡。
- 在 13% 磁吸半徑與 20% 最大偏離之間暫停揭露，不再因連續偏離直接永久失敗；回到附近引導線後恢復。偏離時不推進畫面，抬指時仍偏離不能通過；超過最大偏離、出字框、取消與跳躍輸入仍拒絕。
- 搜尋及回線只在當筆向前最多框寬 12%、且不超過當筆長度 25% 的窗口內；回線另要求相對投影的切線殘差不超過框寬 2.5%／筆長 4%，避免在遠處後段「回線」而跳過中段。短暫離線時略向前移動仍可回線，交叉不可全域搜尋。
- 方向使用扣除起點平移量的原始軌跡副本，獨立做有順序的局部投影；反退超過既有框寬 6% 仍拒絕，保留微抖餘裕。這個平移只用於方向檢查，不改寫原始座標、覆蓋比例或顯示曲線，避免ア轉彎時把容許的固定偏移誤判為反向。
- 開發伺服器內展開「開發：練習容錯調整」，可調五項比例與還原初值。調整會重置目前字元，僅記憶於本頁；不寫入專案資料或 localStorage。最大偏離與磁吸半徑維持一致上下界；筆順、方向及跳段限制不開放關閉。Production build 不包含調參介面。
- 測試改按新的練習意圖驗證：不再把字形不夠精準的舊折線輸入一律拒絕，仍驗證它不會被拿來替換正確標準曲線；保留來源、錯序、反向、跳段、取消與覆蓋比例測試。

## 方向帶寫（目前預設，取代持續按住描完整筆的操作）
- 依使用者新指示，引導模式只要求在當筆起點附近沿正確方向短拉，確認後自動播放並補完標準中心線。放開滑鼠／手指不會中止已觸發的補完；下一筆需要重新起拉，不自動跳筆。自由寫不變。
- `autoTriggerDistance=.04`（框寬 4%，375px 字框約 12 CSS px），短筆取筆長 15% 與前者較小值；起拉淨位移至少門檻 80%，方向夾角不大於 60°，仍須符合起點與貼近條件。只點一下、微抖、反向、先拉後續筆或直接點遠處終點不能觸發。
- 指標移動中一旦方向成立便進入 accepted，清除 active pointer 並釋放捕捉，讓 450ms 正確筆畫動畫獨立完成；後續 pointerup 不會重複提交。清除、切字／切模式會取消待完成動畫。
- 這是筆順與起筆方向練習，不宣稱驗證使用者自行完成整筆及後半段轉折。舊 `finish()` 全筆判定仍保留給幾何回歸測試，畫面引導改用 `finishDirection()`，不再要求 75% 進度。
- 開發調參把完成比例滑桿換成「起拉觸發距離」；參數只存本頁，仍不寫入詞庫或部署。
