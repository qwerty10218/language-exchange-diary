# Codex 分階段實作計畫（省 Token 版）

## 職責切割
- **ChatGPT（這裡）**：需求、風格、單字整理、語義查證、變更決策。
- **Codex Plan Mode（最多 1–2 輪）**：只讀交接文件、列出實作次序、風險、待確認點；不寫程式、不長篇重述。
- **Codex Run**：按階段建立程式碼、完成驗證；若遇授權或缺資料，停止相關任務並回報。
- **專案擁有者**：挑選與確認音檔、確認資料是否可公開、審查修改、批准部署。

## Phase 0 — 技術可行性關卡（務必先做）
- 查證可授權使用的真人日韓錄音，選各 5 個試點；先確認可嵌入 repo、播放且有完整出處。
- 用 `ㅏ`、`あ`、`ア` 做互動字框原型，手機 Safari 指頭與桌面滑鼠可示範、跟寫和取得判定回饋。
- 列出 132 字元的路徑來源與缺漏（5 個緊音子音需補）。
- **停止條件**：素材授權不明、不能取得真實錄音、沒有可靠筆順路徑時，不假裝完成；向維護者提出必要補件。

## Phase 1 — 靜態 App 基礎
- 初始化 Vite + React + TypeScript、簡單 CSS、基礎頁面（首頁／筆記／複習／書寫／關於）。
- 建立奶茶手帳樣式、響應式手機版、語言 Tab 與本機導覽。
- 支援載入與驗證兩份 JSON；沒有登入與後端。

## Phase 2 — 詞庫與更新
- 搜尋原文、中文、個人記音；詳情頁顯示例句、備註、日文假名。
- 提供純 repo 中執行的 JSON 驗證與增量匯入方法；先 diff 後更新，禁止靜默覆寫。
- 本機資料更新→測試→重新部署即可發布。

## Phase 3 — 複習與真人音訊
- 翻卡、配對／單選、基礎拼寫；每裝置 `localStorage` 進度；可重設。
- 導入經審核的 `public/audio` 人聲錄音；單字、例句與字母對應音訊。
- 不支援的音檔顯示缺失，不使用 TTS 自動替補。

## Phase 4 — 書寫功能正式化
- 把 Phase 0 的原型變為共用書寫元件。
- 補齊韓文 40＋平假名 46＋片假名 46 的可用路徑、筆畫序列、動畫和寬鬆判定。
- 測試不同手指大小、橫豎模式、畫布座標與字框比例；不實作漢字筆畫。

## Phase 5 — 驗收與部署
- 依 `docs/QA_CHECKLIST.md` 做手動與自動檢查。
- 用全新裝置或瀏覽器測試公開網址；確認沒有私人內容、授權標示完整。
- 擁有者決定 Commit/Push/部署；不能由 Codex 自動進行。

## Token 與範圍管理
- 在 Plan Mode **只貼一次提示詞**，要求他引用檔案路徑而不是重貼文檔。必要時只做一次補充修訂。
- Run 一次只做一階段並列 `變更檔案 / 驗證 / 問題`，不要反覆重寫全部規格。
- 不建立 SQL Schema、Auth、後台管理、多餘抽象層，也不自動下載大型語料。
- 未完成的外部授權工作應標為 blocker 或待辦，不為追求「完成」捏造資產。
