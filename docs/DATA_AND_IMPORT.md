# 內容與匯入規則

## 資料來源
- `data/ko.entries.json`：朋友教我的韓文。
- `data/ja.entries.json`：我教朋友的日文。
- `data/character_inventory.json`：要練習的韓文 40 字母＋平片假名 92 字元。
- `schemas/entry.schema.json`：每筆詞條資料格式；新增欄位前先更新 schema、測試及說明。
- 對照表只放字元，筆畫軌跡要另外由可用素材衍生或自建，不能從字型外觀猜正確筆順。

## 核心欄位
| 欄位 | 意義 |
|---|---|
| `id` | 穩定且唯一的 ID；更改字面時也不隨便更換 |
| `language` | `ko` 或 `ja` |
| `kind` | `word`、`phrase`、`grammar` |
| `text` | 日文或韓文原文 |
| `meaning_zh` | 繁體中文意思；沒有經查證的意思就標待查 |
| `reading` | 日文假名或韓文發音標示；可為空 |
| `romaji` | 標準羅馬字；可為空；不等同個人中文式記音 |
| `personal_mnemonic` | 朋友教的自創記音，應忠實保存；可為空 |
| `examples` | 原文、中文翻譯；必要時保留獨立讀音 |
| `notes` | 語氣、使用場景、教學備註；非對話紀錄 |
| `review_status` | `needs_review` / `verified` |
| `audio` | 經審核之真人錄音資訊；不存在就用 `null` |

## 漢字注音
- 日文詞條 `text = "美しい"`、`reading = "うつくしい"`，前端可顯示 ruby（振假名）。
- 對多漢字／混合文字的詞，若逐字注音有歧義，資料可擴展 `ruby_segments`；**不要求 Codex 自行猜測每段標註**。
- 漢字不進入筆順練習。

## 內容維護（無網站編輯介面）
1. ChatGPT 根據新的教學內容生成相同 schema 的新詞或更新片段。
2. 維護者複查原文、意思、例句、記音，避免把推測當翻譯。
3. Codex 驗證 JSON schema、language 值、ID、重複詞條；只更新對應語言檔。
4. 有衝突時輸出差異，**不得靜默覆蓋**。除明確指示外，不刪既有筆記／備註。
5. 修改完成後本機測試、由維護者批准部署。

## 目前注意事項
- 樣本只是起始詞庫示例，不代表所有過往日韓筆記已完整匯入。
- `needs_review` 內容未經逐項查核。不要為了讓畫面完整而自動改成 `verified`。
- 原始例句若來自私人聊天，在公開網站使用前請改成不含個資的一般示例。
- `audio` 必須驗證 `kind="human_recording"`、本地路徑、逐檔授權、語言與發音內容。
- 不加入未取得同意的朋友真人錄音。
