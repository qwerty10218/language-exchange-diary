# MVP 閱讀主題與低光驗收

本文件是 MVP 正式驗收條件。數值檢查不能取代真人的夜間閱讀、低亮度或手機操作驗收，也不代表網站已取得整體 WCAG 認證。

## 實作與維護

- 色彩唯一來源為 `src/themes.css` 的 `--light-*`／`--dark-*` 色票；共用語意 Token 包括 page、paper、ink、muted、control-border、rose、error、success 及各狀態背景／邊框。元件與其他 CSS 不再散落色碼。
- 預設 follows `prefers-color-scheme`，提供「自動／淺色／深色」三個至少 44px 的按鈕，使用 ✓ 與 aria-pressed 標示選擇。系統在網站開啟時改色會即時反應；手動選擇不受系統變動覆寫。
- 外觀偏好以 `language-exchange-diary:theme:v1`、`{version:1,mode}` 保存。讀取不寫入；只有使用者明確點選才保存。儲存失敗仍即時套用並提示，不修改任何測驗或翻卡資料。
- HTML 在應用程式啟動前讀取合法偏好，色票以 head stylesheet 載入，降低先出現錯誤主題的閃白。所有學習頁及書寫入口共用根節點主題，不因切頁重設。
- Light 為米白、奶茶、暖棕。Dark 為低亮度暖灰／棕，沒有純黑背景或純白文字。
- 假名標示：柔和陶土紅／豆沙紅＋淡背景＋2px 邊框＋◆。點字後仍保留單字標示，另外增加輪廓；平片假名不互相轉標。
- 答錯另用暖琥珀色與 ✕／說明文字；答對用鼠尾草綠與 ✓。停用按鈕用虛線、停用語意與可讀文字，不以降低整體透明度使字變淡。
- 移除介面陰影，提高字母羅馬拼音／狀態字級；遵守 reduced-motion。既有必要的逐筆示範動畫保留，判定器、中心線與詞庫不改。

## 已執行的自動檢查

`npm run check` 包含 TypeScript、資料／書寫 QA、205 項測試及 Production Build。主題新增測試檢查色票、CSS 變數完整性、系統／手動解析、非破壞儲存、載入前偏好，以及三種主題在詞庫／字母表／測驗的實際 React SSR 輸出。

| 檢查 | 結果與範圍 |
|---|---|
| 一般文字 | ink／muted／link 在頁面、卡片、柔和底色、選取及回饋底色均 ≥4.5:1 |
| 主要按鈕、假名與回饋文字 | 前景／背景配對均 ≥4.5:1；假名文字 Light 約 4.82:1、Dark 約 5.67:1 |
| 重要非文字狀態 | 按鍵邊界、焦點、假名與正誤邊框在相鄰表面均 ≥3:1；純裝飾分隔線不作為狀態辨識 |
| 多字標示 | SSR 確認 `かさ` 2 格、`すいか` 3 格；仍保留 ◆ 與讀屏標籤 |
| 偏好保存／切頁 | 單元測試及 SSR 通過；尚未以實際瀏覽器點擊確認 |

對比計算依 sRGB 相對亮度，不把系統亮度百分比當作 WCAG 對比值。參考 [W3C 文字對比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字對比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 及 [不只依賴顏色](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。

## 正式人工驗收條件（目前均待驗）

| 情境 | 必須確認 |
|---|---|
| Light 日間閱讀 | 詞義、備註、羅馬拼音、次要說明均容易辨認；奶茶風格未被強烈邊框破壞 |
| Dark 夜間閱讀 | 無大面積亮白或閃白；背景、卡片、鍵盤與正誤回饋一致；文字舒適但不灰暗難讀 |
| 手機降低亮度 | 在使用者常用低亮度下辨認細筆假名、◆、邊框、焦點與正誤圖示；不可只靠紅色辨識 |
| 多個字元標示 | 測 `すいか`、重複假名與較長詞；標示明顯且無刺眼色塊，不標錯另一字形 |
| 詞庫→查表→測驗 | 依序切換三種主題與學習頁；未送答案、題目、統計及標示不丟失；重開後偏好一致 |

另測 320／375px、系統主題在開啟期間變化、手動淺色配深色系統及反向組合。瀏覽器工具先前受安全政策阻擋，本次未繞過；真實日夜環境與實機閱讀未驗證。

已知建置提示：主要 JS bundle 約 500KB，Vite 提供分包大小警告，但 build 成功；本次未提高警告門檻或改寫無關架構。未 Commit、Push 或部署。
